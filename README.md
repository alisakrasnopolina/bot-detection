# Детекция ботов по поведенческим данным

Решение тестового задания по бинарной классификации пользователей на основе истории событий.

Цель задачи — для каждого `cookie_id` определить вероятность того, что пользователь относится к сервису автоматизированного сбора данных.

- `target = 1` — бот;
- `target = 0` — обычный пользователь.

Основная метрика — **Precision при Recall ≥ 0.70**.

## Результаты

Финальное решение использует **111 признаков** и ансамбль двух моделей:

- CatBoost;
- LightGBM.

Для оценки качества используется временная валидация, поскольку обучающая и тестовая выборки относятся к последовательным временным периодам.

Полученные результаты:

| Выборка | Precision@Recall≥0.70 |
|---|---:|
| Temporal CV, среднее | ~0.912 |
| Holdout 17–19 апреля | ~0.882 |

## Подход

### 1. Поведенческие признаки

Для каждого cookie рассчитываются агрегированные характеристики активности:

- количество событий;
- количество уникальных типов событий;
- количество просмотренных товаров и категорий;
- число поисковых запросов;
- продолжительность активности;
- интенсивность событий;
- характеристики платформы и User-Agent;
- pointer-признаки;
- повторяемость действий.

### 2. Временные признаки

Используются характеристики интервалов между последовательными событиями:

- среднее и медианное время между действиями;
- квантили интервалов;
- стандартное отклонение;
- доля коротких интервалов;
- повторяемость временных промежутков.

Эти признаки позволяют учитывать скорость и регулярность поведения пользователя.

### 3. Исторические признаки товаров

Для `item_id` рассчитываются статистики его появления у ранее наблюдавшихся пользователей.

При построении признаков обучающей выборки используется только информация, доступная к соответствующему моменту времени. Данные из будущих периодов не используются.

### 4. Исторические признаки пересечения cookie и товаров

Дополнительно анализируется сходство текущего cookie с ранее наблюдавшимися cookie через общие `item_id`.

Рассчитываются:

- количество исторических соседей;
- количество bot- и human-соседей;
- число соседей с несколькими общими товарами;
- максимальное и среднее число общих товаров;
- доля bot-соседей;
- weighted bot rate;
- Jaccard similarity;
- максимальное сходство с bot- и human-cookie.

При построении train-признаков используются только cookie, для которых:

```text
window_end_ts <= current window_start_ts
```

Таким образом, исторические значения `target` используются без утечки информации из будущего.

## Временная валидация

Случайное разбиение train/validation не используется, поскольку данные имеют временную структуру.

Для оценки решения используются четыре последовательных временных validation-периода. Модель на каждом этапе обучается только на более ранних данных.

Дополнительно период **17–19 апреля** используется как holdout-выборка и не участвует в выборе параметров модели.

Такой способ валидации соответствует реальному сценарию задачи: необходимо делать предсказания для более позднего периода на основе уже накопленной истории.

## Модели

Финальное решение использует две модели градиентного бустинга:

- CatBoost;
- LightGBM.

Гиперпараметры были выбраны по результатам экспериментов на temporal validation и затем зафиксированы.

Перед объединением предсказания моделей преобразуются в percentile ranks.

Финальный score рассчитывается как:

```text
score =
    0.60 × rank(CatBoost)
    + 0.40 × rank(LightGBM)
```

## Как воспроизвести результат

### 1. Клонировать репозиторий

```bash
git clone <URL-РЕПОЗИТОРИЯ>
cd bot-detection
```

### 2. Создать виртуальное окружение

Решение разрабатывалось с использованием **Python 3.11**.

Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
```

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Добавить данные

В корне проекта необходимо создать папку `data` и поместить в нее исходные файлы:

```text
data/
├── train.csv
├── test.csv
├── events.csv.gz
└── sample_submission.csv
```

После этого структура проекта должна выглядеть так:

```text
bot-detection/
├── bot_detection_final.ipynb
├── metric.py
├── requirements.txt
├── README.md
└── data/
    ├── train.csv
    ├── test.csv
    ├── events.csv.gz
    └── sample_submission.csv
```

### 5. Запустить Jupyter Notebook

```bash
jupyter notebook
```

Открыть:

```text
bot_detection_final.ipynb
```

и выполнить все ячейки последовательно:

**Kernel → Restart Kernel and Run All Cells**

При корректном выполнении финальные матрицы признаков имеют размер:

```text
Train: (11091, 111)
Test:  (4909, 111)
```

Перед сохранением результата notebook также проверяет количество предсказаний и корректность submission.

Ожидаемый вывод:

```text
Models trained on: 111 features
Predictions: 4909 4909
Submission validation: OK
```

### 6. Получить итоговый файл

После выполнения notebook создается:

```text
submission_overlap_111.csv
```

Файл содержит две колонки:

```text
cookie_id,score
```

и 4909 строк — по одной для каждого объекта тестовой выборки.

## Воспроизводимость

Для воспроизводимости используется фиксированный:

```python
SEED = 42
```

Random seed передается в используемые модели.

Исторические признаки строятся с соблюдением временного порядка, поэтому при обучении и валидации не используется информация из будущих периодов.
